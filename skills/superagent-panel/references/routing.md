# 怎么派活

我的秘书（Superagent）派活时照这里做（这份会整份写进它的说明里）。工作目录列表、worker 默认用哪个 agent 和模型，
在面板的「设置」里，也会一起写给它。

## 挑工作目录

- 看任务说的是哪个服务、哪个产品，对照仓库的说明挑。
- 拿不准就先在候选的几个仓库里搜一下相关代码再定；还定不了，问我。
- 列表里的是「工作目录」：多数是仓库，也可以是普通文件夹。说明里写着「通用」的那个，是给不属于任何仓库的活用的。
- 一件事涉及好几个仓库：**不拆成几个任务**，派给一个 worker。挑改动最多、或者最后交付在那里的仓库当它的目录，
  prompt 里写上还涉及哪些仓库（绝对路径）；别的仓库里的活它直接进去做。
  几个仓库分不出主次，就派到通用工作目录，同样在 prompt 里写上涉及的仓库。
- 调研、写东西、一次性的脚本，做完不用留在哪个仓库里的：派到通用工作目录。
- 要长期留着、以后还会接着改的独立小东西（单页 demo、试验项目）：别借一个沾边的仓库，以前有类似的活放在哪里也不算数，
  也别放进通用工作目录。问我，建议新建一个目录，写出完整路径（放在我常用仓库的旁边）；我同意了就先 `mkdir -p` 建好再派。
- 要派去的目录不在工作目录列表里：先问我，别先派了再在回复里说明「它不在你的列表里」。

## 挑模型

- 一般用默认，不用另外给。
- 改动大、要跨好几个模块想清楚的，可以换更强的模型（parts 里带 `model`、`effort`）。
- 只是查个资料、改个文案的，换便宜的。
- 我点名了某个模型或版本（「用 fable 5.2」）：照「可选的模型」里名字对得上的 id 填。对不上就告诉我有哪些，别换一个凑合。
