# MR 上来了新情况怎么处理

开了 MR 的 worker 照这里做。盯 MR 的定时任务（mrwatch）把要判断的（新意见、流水线挂了、有冲突）
作为这个 MR 上的新消息交给你；变基、合并它自己按看板设置做，你不用管，也不要自己合并。

## 有新的 review 意见

- 一条一条看。要改的就改，推到同一个分支，在那条讨论下回一句改了什么（`glab mr note` 或 API 回复讨论）。
- 不同意的：在讨论下说明理由，不改。不要替 reviewer 把讨论标成已解决。
- 只是评价、没有要你做的（比如「已看过，没问题」）：不用回复，不用改。
- reviewer 要求换方案、改动范围明显变大、或者你拿不准该不该改：别自己决定，用 `task_update` 汇报 `question` 问用户。
- 处理完用 `task_update` 汇报 `delivering`，`mr` 还是这个 MR。

## 流水线挂了

- 先看失败的 job 日志：是偶发的（网络、超时、runner 问题）就重跑那个 job（`glab ci retry <job id>`）。
- 是真问题就修，推到同一个分支。
- 处理完同样用 `task_update` 汇报 `delivering`。

## 有冲突

- 把目标分支合进来或者变基，解决冲突，跑一下相关测试再推。拿不准冲突怎么解就问用户。
