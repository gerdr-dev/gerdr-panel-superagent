# 在看板上做事（worker）

我看的是看板，不看你的对话。你是看板派出去的 worker 时，照这里做。

## 每次停下，看板上都要说清现在怎样

- 用看板的工具汇报，不要只写在对话里：只在对话里说的话，我看不到。
- 每一轮结束前，用 `task_update` 报一下：
  - `working`：还在做，写一句进展；
  - `done`：做完了，没有要我判断的；
  - `review`：结论要我来判断（排查、调研的结果）。
- 只有你（或我）说任务做完了才算完：MR 合并了、流水线过了，都只是发给你的消息，后面还有事就接着做。
- 要我拍板、或者要我亲手做一步：用 `ask_human`，然后结束这一轮，具体见 [human.md](human.md)。
- 给我看的东西（截图、样片、录屏）用 `![](/绝对路径)` 写进步骤或总结里，看板和对话里都会直接显示 / 播放。

## 等别人

- 你在等别人：同事回私信、点个按钮，或者等 job、发布跑完。这时用 `wait_for` 说清等什么，然后结束这一轮。
- 光在对话里说「我在等」没用：这一轮一结束，就没有东西会叫醒你。
  - 等人回话：`conversation` 填你发消息的那个对话，比如 Slack 的频道 / 私信 id，或者 MR 地址。对方在那里一回复，就会转给你。
  - 等状态变化：`recheck` 填几分钟后回来看，没人会为这类事发消息。
  - 两种可以一起用：等人点 Retry，就同时盯私信、再定时看 job。
- 等着的时候，卡片留在「进行中」，显示你在等什么。
- 被叫醒后，有结果就照常做、照常汇报；还没好，就再 `wait_for` 一次。
- 能自己查的不要让我去催，比如 job 状态、MR 状态、对方回没回。
- 开了 MR 也一样：`wait_for` 填 MR 地址，MR 上的 review、流水线、可以合、合并了都会发给你。具体见 [mr.md](mr.md)。

## 你自己开的会话

- 你用 `gerdr session new` 开出去的会话，问的问题是在问你，不是问我：能定的你直接回答它
  （`gerdr session send <会话> "回答"`，给它发消息就是回答它的问题）。
- 真要我拿主意的，用 `ask_human` 带上选项和你的建议问我；我答了，你再发给它。
- 它要批准命令（审批）只有我能批：在看板上告诉我去批哪个会话的哪一步。

## 对话里接着来的话

- 原对话（私信、thread、MR 上的评论）里接着来的话，是你这个任务的就照常做、汇报，结果会转回去。
- 超出这个任务、或者是别的任务的事：用 `hand_back` 交回，不要自己答。
