# 活动里记什么

每个任务（一个人做，还是几个成员一起做）我都只看它的活动，不看你的对话。活动是给我看的，要少，一眼看完。

## 记

只记你手上的事告一段落的时候：

- 你这部分做完了、交出去了（交给队友，或者等我看）。
- 你手上的做完了，开始等你控制不了的事：等队友（前端联调结果）、等外部（CI 跑完、发布、同事审批）、等我（定样式）。
- 你停下了、手上没事了。

做完（`task_update` 报 `done` / `review`）、问我（`ask_human`）、开始等（`wait_for`，`what` 就是记进去的那一行，写清等谁、等什么）、
等到了（检查命中、有人回复）、拉队友进来、撤回问我的事、我在你对话里说的话，看板都会自己记一笔，不用你再写。「停下了」用 `message_user` 写一行。

`message_user` 是你对我说话的唯一方式：我在面板里问你的，用它回；告一段落时的结论，也用它说。

**等到的东西有了结果，先说结果再等下一件。** 看板只记「等到了：审批通过」，不知道后面怎么样了。你接着发布、核验，
有了结论（上线了、核验通过、跑出来了但不全），用 `message_user` 写一行，再 `wait_for` 下一件。
不写的话，我在活动里看到的是「等审批」「等审批」「等任务跑完」，中间最要紧的「修复已上线、核验通过」没了。

**要我选的，只用 `ask_human`（带 options），不要再报 `review`。** 「有结论了，等你看」是让我验收；
还有事要我定的时候，看板不接受 `review` / `done`。

## 不记

过程一律不记：写了哪个功能、在跑单测、在改 bug、在排查、换了个做法。这些我不关心，要看的话我去你的对话里看。

分界是「是不是你自己手上的活」：你自己在本地跑单测是过程，不记；代码推上去了，等 CI 跑完，是你做完了在等外部，要记（用 `wait_for`）。

## 和队友说话时

`tell` 只有在交接的时候才写 `summary`（会进活动）：你做完了交给它、它要的东西你给了。
来回讨论细节、报错、追问，不写 `summary`，就不进活动。
