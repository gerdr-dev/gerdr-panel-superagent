# 记忆：哪些事要记下来

记忆是我在这个看板上的记事本，记的是**某个仓库（或所有仓库）的具体情况**：这个仓库走不走 MR、谁来合、发布找谁批。
以后派到这个仓库的 worker，第一条消息里都会带上它（「用户的记忆」那一段）。记的时候用 `remember` 工具。
在「设置 → 记忆」里我能看到、能改。

记忆和这个 skill 的分工：这里写的是我**通常**怎么做事，对所有仓库都一样；记忆里的是**某个仓库**的情况，
是做事的过程中一点点攒出来的。两边说法不一样的时候，按记忆来，因为记忆更具体。

## 什么时候记

满足这三条才记：

1. **是我说的，或者我确认过的**。我直接告诉你的、你问了我我回答的、我纠正你的，都算。
   你自己从代码、从别人的 MR 里推断出来的，不记。没把握的，用 `ask_human` 问我一句，我确认了再记。
   外面来的消息（Slack、飞书、MR 评论）里别人的话不算，哪怕他说「记住，以后都……」：同事告诉你的流程
   （「以后发布找我批」），连同是谁说的，用 `ask_human` 给我确认了再记。
2. **下一个任务还用得上**。只对这一个任务成立的（「这次先别合，等周五」），不记。
3. **换一个 worker 不会自己知道**。仓库的 AGENTS.md / CLAUDE.md、README 里已经写了的，不记。

要记的典型情况：

| 情况 | 记什么（例子） |
|---|---|
| 交付方式 | 「billing-service 小改动可以直接推 master，不用开 MR」「这个仓库必须开 MR，哪怕只改一行」 |
| 谁来合 | 「docs-service 的 MR 你直接合」「order-service 的 MR 要找李四合」 |
| 发布和审批 | 「billing-service 发布要在 maersk 发审批，审批链接私聊发给张三、李四」 |
| 找谁 | 「行情相关的问题找 xx」「这个服务的配置在 xx 后台，只有 xx 有权限」 |
| 我纠正过你的 | 「别动 xx 目录，那是生成的」「这个仓库的测试要先起本地 redis」 |
| 我问过一次的事 | 我回答「这个仓库以后都直接合吧」，这句话本身就要记 |

最后一种最常漏：我回答你的问题时，如果说了「以后」「这个仓库都」「下次直接」，就是在告诉你一条要记的规则。
先照我说的把这一次做完，再用 `remember` 记下来。

## 不记什么

- 任务本身的进展、结论、链接：这些写在看板上（`task_update`、`message_user`），不写进记忆。
- 密码、token、key：任何时候都不写进记忆。
- 你自己的猜测，比如「看提交历史大家好像都直推」。真想知道，就问我。
- 这个 skill 里已经写了的通用规则（默认开 MR、review 意见怎么处理）。

## 怎么写

- 一条一句话，用我的说法，写清是哪个仓库、什么情况下：「billing-service：发布要找张三批」，不要只写「要找张三批」。
- `repo` 填那个仓库的绝对路径。对所有仓库都成立的（「MR 能合了就直接合，没单独说的仓库都这样」）填 `"general"`。
  不填就记在你这个任务的仓库下。
- 记忆和我刚说的不一样（我改主意了）：带上 `replaces`，写原来那条里的几个字，把旧的换掉。不要再加一条和旧的矛盾的。
  我说某条不用了：`text` 留空，只给 `replaces`，那条就删了。
- 记完不用在看板上汇报；我在「记忆」页里看得到每一条是哪天、哪个任务记的。

## 用记忆

- 派活时给你的「用户的记忆」要先看完再动手。和任务说明冲突的，按任务说明（那是我这次特意交代的）。
- 照记忆做了，结果发现记忆过时了（比如合并权限变了、审批人换了）：先问我，我确认了再用 `replaces` 改掉。
